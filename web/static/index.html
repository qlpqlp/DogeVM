admin_panel_settings API tokens

Leave both empty for open access on this computer. Set an admin token to lock the interface and key export. A user token can generate a wallet, unlock it, send, and bridge, and cannot export the key or change these tokens.

key This browser

The page sends this value as Authorization: Bearer. Saving an admin token above stores it here too. A new browser needs the admin token pasted again.

Config file: connect_config.json in the wallet data folder. Env DOGEVM_USER_TOKEN and DOGEVM_ADMIN_TOKEN override the file on startup.

api HTTP API

Base URL for this app: http://127.0.0.1:8787. Send Authorization: Bearer TOKEN or X-Token: TOKEN when tokens are on. You can also prefix the path: /ADMIN_OR_USER_TOKEN/api/.... Drop the header when both tokens are empty. Add "preview": true to any send or bridge call to see fees without broadcasting.

User token: create, unlock, balances, send on either chain, bridge both ways, confirmations. Admin token: those, plus export, delete wallet, and token settings. The same key is a D... address on Dogecoin L1 and on DogecoinVM. Balances are separate.

1. Generate a wallet

Creates a new key, encrypts it with the passphrase, and unlocks it. Fails if a wallet file already exists.

curl -s -X POST http://127.0.0.1:8787/api/wallet/create \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"passphrase\":\"choose a long passphrase\"}"
const created = await fetch("http://127.0.0.1:8787/api/wallet/create", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer YOUR_TOKEN",
  },
  body: JSON.stringify({ passphrase: "choose a long passphrase" }),
}).then((r) => r.json());
console.log(created.address);

2. Unlock a wallet

Needed after a restart before send or bridge. Balance and confirmation reads work from the address on disk even while locked.

curl -s -X POST http://127.0.0.1:8787/api/wallet/unlock \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"passphrase\":\"choose a long passphrase\"}"
await fetch("http://127.0.0.1:8787/api/wallet/unlock", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer YOUR_TOKEN",
  },
  body: JSON.stringify({ passphrase: "choose a long passphrase" }),
});

3. Balances on both chains

spendable is confirmed UTXOs (at least 1 confirmation) in DOGE. data.confirmed and data.pending come from the DogecoinVM index.

curl -s http://127.0.0.1:8787/api/balances \
  -H "Authorization: Bearer YOUR_TOKEN"
const bal = await fetch("http://127.0.0.1:8787/api/balances", {
  headers: { Authorization: "Bearer YOUR_TOKEN" },
}).then((r) => r.json());
console.log(bal.chains.dogecoin.spendable, bal.chains.dogecoinvm.spendable);

4. Send Dogecoin L1 to another L1 wallet

chain is dogecoin. This does not bridge.

curl -s -X POST http://127.0.0.1:8787/api/send \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"chain\":\"dogecoin\",\"to\":\"Dxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx\",\"amount\":\"1.5\"}"
const sentL1 = await fetch("http://127.0.0.1:8787/api/send", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer YOUR_TOKEN",
  },
  body: JSON.stringify({
    chain: "dogecoin",
    to: "Dxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    amount: "1.5",
  }),
}).then((r) => r.json());
console.log(sentL1.txid, sentL1.confirm);

6. Bridge Dogecoin L1 into DogecoinVM

Builds a Dogecoin payment to your verified deposit address. Credit lands on this same address on DogecoinVM, minus the bridge fee, after Dogecoin confirmations.

curl -s -X POST http://127.0.0.1:8787/api/bridge/deposit \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"amount\":\"10\"}"
const deposit = await fetch("http://127.0.0.1:8787/api/bridge/deposit", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer YOUR_TOKEN",
  },
  body: JSON.stringify({ amount: "10" }),
}).then((r) => r.json());
console.log(deposit.txid, deposit.depositAddress);

7. Bridge DogecoinVM back to Dogecoin L1

to is the Dogecoin address that should receive the payout. It can be this wallet or any other L1 address.

curl -s -X POST http://127.0.0.1:8787/api/bridge/withdraw \

  -H "Content-Type: application/json" \

const withdraw = await fetch("http://127.0.0.1:8787/api/bridge/withdraw", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer YOUR_TOKEN",
  },
  body: JSON.stringify({
    to: "Dzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzz",

8. Confirmations and available balance

confirmed means the transaction has enough confirmations for that flow. available means funds are ready: spendable balance on that chain after a same-chain send, DogecoinVM credit after a deposit, or a Dogecoin payout with at least 1 confirmation after a withdraw. balance.spendable is always this wallet.

curl -s "http://127.0.0.1:8787/api/confirm?flow=send&chain=dogecoin&txid=TXID" \
  -H "Authorization: Bearer YOUR_TOKEN"

curl -s "http://127.0.0.1:8787/api/confirm?flow=send&chain=dogecoinvm&txid=TXID" \
  -H "Authorization: Bearer YOUR_TOKEN"

curl -s "http://127.0.0.1:8787/api/confirm?flow=deposit&txid=L1_TXID" \
  -H "Authorization: Bearer YOUR_TOKEN"

curl -s "http://127.0.0.1:8787/api/confirm?flow=withdraw&txid=VM_TXID" \
  -H "Authorization: Bearer YOUR_TOKEN"
async function waitReady(params) {
  const headers = { Authorization: "Bearer YOUR_TOKEN" };
  for (let i = 0; i < 120; i++) {
    const q = new URLSearchParams(params);
    const data = await fetch("http://127.0.0.1:8787/api/confirm?" + q, { headers })
      .then((r) => r.json());
    if (data.confirmed && data.available) return data;
    await new Promise((r) => setTimeout(r, 3000));
  }
  throw new Error("timed out waiting for confirmation");
}

await waitReady({ flow: "send", chain: "dogecoin", txid: sentL1.txid });
await waitReady({ flow: "send", chain: "dogecoinvm", txid: sentVM.txid });
await waitReady({ flow: "deposit", txid: deposit.txid });
await waitReady({ flow: "withdraw", txid: withdraw.txid });

dark_mode Night side

DogecoinVM on Metal

  • Fast finality. Payments settle in roughly a fifth of a second.
  • Same address. Your D… key works here - balances are separate from mainnet.
  • Withdraw home. Bridge out with a tagged payment to the reserve (DVMO).

light_mode Day side

Dogecoin mainnet

  • Header cadence. New blocks about once a minute - the slow gauge on Home.
  • Deposit to bridge. Only your personal deposit address moves DOGE onto DogecoinVM.
  • Keys stay local. DogeVM Connect signs on this machine; keys never go to the API.
